# 2. 🔴 P0 mới: expression `capital_allocation.status` có thể crash

Trong `app/main.py` commit mới thêm:

```python
"status": "EXCELLENT" if (
    avg_roe_5y
    and avg_roe_5y >= 18
    and confirmed_dilution is None
    or confirmed_dilution < 5
) else ...
```

Code thực tế đang viết một dòng nhưng semantics tương đương như trên.

Do precedence:

```text
and > or
```

nó thực sự được evaluate thành:

```python
(
    avg_roe_5y
    and avg_roe_5y >= 18
    and confirmed is None
)
or confirmed < 5
```

### Case rất dễ xảy ra

```text
avg_roe_5y = 12
confirmed_economic_dilution_pct = None
```

Left side = false.

Python tiếp tục evaluate:

```python
None < 5
```

→ **`TypeError`**

Tức chính trường hợp:

```text
UNEXPLAINED_SHARE_CHANGE
confirmed dilution = null
ROE < 18
```

có khả năng làm valuation/report endpoint crash.

### Cần sửa ngay

Tách biến:

```python
confirmed_dilution = (
    dilution_breakdown or {}
).get("confirmed_economic_dilution_pct")

if (
    avg_roe_5y is not None
    and avg_roe_5y >= 18
    and (
        confirmed_dilution is None
        or confirmed_dilution < 5
    )
):
    status = "EXCELLENT"
elif avg_roe_5y is not None and avg_roe_5y >= 13:
    status = "GOOD"
else:
    status = "WATCH"
```

Tôi sẽ thêm regression test:

```python
confirmed_dilution = None
avg_roe = 12

assert no_exception
assert status != "EXCELLENT"
```

Đây là **blocker merge**.

# 3. Leverage penalty: tốt hơn nhưng chưa thật sự tách khỏi hard reject

Commit thêm `_leverage_penalty()` với:

```text
net cash                     → 0
ND/EBITDA >= 2               → +3
ND/EBITDA >= 4               → +6
ND/EBITDA >= 6               → +10

debt payback >= 2y           → +3
debt payback >= 5y           → +6
debt payback >= 10y          → +10
```

Cấu trúc này tốt hơn bản trước rất nhiều.

Nhưng engine vẫn gọi:

```python
has_solvency_risk = len(
    quality_scorecard.hard_rejects
) > 0
```

Đây vẫn sai.

Ví dụ:

```text
hard_rejects = [EXCESSIVE_DILUTION]
net_debt = 0
```

thì:

```python
has_solvency_risk = True
```

và `_leverage_penalty()` chạy dòng đầu:

```python
if has_solvency_risk:
    return 10.0
```

→ công ty **net cash** nhưng bị leverage penalty +10 chỉ vì dilution.

### Phải là

```python
has_solvency_risk = (
    HardRejectReason.SOLVENCY_RISK
    in quality_scorecard.hard_rejects
)
```

Không phải:

```python
len(hard_rejects) > 0
```

Regression test cần:

```text
net_debt = -5T
hard_reject = EXCESSIVE_DILUTION

expected leverage penalty = 0
```

Hiện test net-cash không truyền hard reject nên không bắt được bug này.

# 4. Hard reject precedence cũng còn một edge case

Code tính:

```python
reject_override =
    SOLVENCY_RISK → AVOID_SOLVENCY
    UNNORMALIZABLE → UNVALUABLE
    otherwise → AVOID_QUALITY
```

nhưng sau đó:

```python
if quality_tier == LOW_QUALITY:
    verdict = AVOID_QUALITY
```

và reject override chỉ được áp khi verdict hiện tại là:

```text
HIGH_CONVICTION
ATTRACTIVE
FAIRLY_VALUED
```

Do đó:

```text
LOW_QUALITY
+
SOLVENCY_RISK
```

có thể cuối cùng vẫn là:

```text
AVOID_QUALITY
```

thay vì:

```text
AVOID_SOLVENCY
```

Tương tự:

```text
LOW_QUALITY
+
UNNORMALIZABLE_EARNINGS
```

có thể không trở thành `UNVALUABLE`.

Nên precedence rõ:

```python
if SOLVENCY_RISK:
    AVOID_SOLVENCY
elif UNNORMALIZABLE / CIRCLE_FAIL:
    UNVALUABLE
elif quality == LOW_QUALITY:
    AVOID_QUALITY
...
```

# 6. Nhưng `confirmed economic dilution` vẫn chưa thực sự được chứng minh

Đây là vấn đề sâu hơn.

Classifier hiện làm:

```python
if residual >= 20 and economic_events:
    classification = "EXCESSIVE_DILUTION"
```

rồi:

```python
confirmed_economic_dilution_pct = residual
```

Tức chỉ cần tồn tại **một** economic event là toàn bộ residual được coi confirmed.

Test commit mới tự cho thấy vấn đề:

```text
shares old = 100

bonus share 100%
→ expected = 200

actual shares = 300
→ residual = 100%

RIGHTS_ISSUE event ratio = 50%
```

Nhưng code kết luận:

```text
confirmed economic dilution = 100%
```

Trong khi event được cung cấp chỉ nói rights issue 50%.

Quan trọng hơn nữa:

> Có phát hành cổ phiếu không đồng nghĩa 100% với economic value dilution.

Nếu phát hành gần fair value và công ty nhận tài sản/cash tương ứng thì economic dilution khác rất nhiều ESOP giá rẻ.

### Audit-grade classifier cần

Ít nhất:

```text
event_type
shares_issued
issue_price
market/reference price
cash/proceeds received
ownership transfer
convertible terms
```

Ví dụ:

$$
ValueTransfer =
SharesIssued \times
\max(FairValue-IssuePrice,0)
$$

rồi mới ước lượng economic dilution.

Hiện classifier mới chứng minh:

```text
share issuance occurred
```

chưa chứng minh:

```text
economic value destroyed = residual share increase
```

Tôi xếp phần này **P1 correctness**, chưa P0 vì engine giờ đã ít nguy hiểm hơn trước.
