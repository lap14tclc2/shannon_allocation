# Tôi phát hiện một lỗi mới: `net_debt_to_ebitda` sai unit

FRT hiện ghi:

```json
"net_debt": 15705000000000,
"debt_payback_years": 5.7,
"net_debt_to_ebitda": 9152097902.1
```



`Net Debt / EBITDA` phải là **dimensionless ratio**, kiểu:

```text
0.5x
2.0x
5.7x
```

không thể là:

```text
9,152,097,902.1x
```

Tôi parse toàn export và thấy pattern tương tự ở nhiều mã:

```text
SCS  ≈ 541,484,716
DGC  ≈ 954,503,817
FRT  ≈ 9,152,097,902
CMG  ≈ 6,491,860,465
VJC  ≈ 20,685,902,556
```

Pattern rất giống **unit mismatch ×1e9**:

```text
net_debt = VND
EBITDA   = billion VND
```

rồi divide trực tiếp.

Ví dụ SCS khoảng:

```text
541,484,716 / 1e9
≈ 0.541x
```

là một ratio hợp lý.

### Cần canonicalize

```python
net_debt_to_ebitda = (
    net_debt_vnd / ebitda_vnd
)
```

không:

```python
net_debt_vnd / ebitda_billion_vnd
```

Tôi xếp bug này **P1** vì leverage penalty hiện dường như vẫn đi theo debt-payback/normalized logic — SCS ratio payload rất lớn nhưng penalty vẫn 0. Tuy vậy machine evidence field đang sai và bất kỳ consumer nào dùng field này trực tiếp sẽ cho kết quả cực kỳ sai.

Nên thêm invariant test:

```text
0 <= ND/EBITDA < ~100
```

với giá trị ngoài range phải fail validation.
